# Политика обновлений MSB на серверах

## Принцип

Обновление затрагивает **только файлы бота и системы**.  
Пользовательские файлы, настройки и накопленный контекст **не затираются**.

Это относится к: ручному `rsync`/`bootstrap`, puller/sync с бэкенда, выкладке `ext/`,
скриптам админа, «починить сервер копией из репо».

## Два слоя

| Слой | Примеры | При обновлении |
|------|---------|----------------|
| **Система / бот** | `.msb/bot/index.js`, `bot/ext/**` (если так задумано), `puller.cjs`, `sync.cjs`, `guard/`, `dialogue-mcp/`, `/usr/local/bin/bot-ctl.sh`, `msb-engine`, unit’ы `msb-*`, package-lock бота | Можно **заменять** целиком (с откатом по политике платформы) |
| **Владелец / инстанс** | `workspace/CLAUDE.md`, `SOUL.md`, `USER.md`, `MEMORY.md`, `memory/**`, `ops/**` (учёт, реестры), `avatar/**`, `projects/**`, `.msb/.env`, `bots/<id>/.env`, `bots/<id>/state.json`, sessions/transcripts/traces, `ext-providers.json` | **Не перезаписывать** wholesale. Только seed при *первой* установке или явный запрос владельца |

`bootstrap/install.sh` на уже живом сервере **не** должен молча делать `rsync --delete` по `workspace/`.  
Повторный прогон: система — да; workspace — только если передан явный флаг вроде `--reset-workspace` (осознанный сброс).

## Документы workspace (CLAUDE.md и подобные)

Если платформе нужно добавить правила в `CLAUDE.md` / `SOUL.md` / skill:

1. **Запрещено** подменять файл целиком копией из репо/бандла.
2. **Разрешено** умное обновление: вставить или обновить только блоки с маркерами:

```markdown
<!-- MSB-SYSTEM-BLOCK:example-id -->
…текст от платформы…
<!-- /MSB-SYSTEM-BLOCK:example-id -->
```

3. Всё вне таких блоков — данные владельца; merge их не трогает.
4. Инструмент: `bootstrap/merge-workspace-block.sh` (идемпотентная замена блока по id).
5. Новый файл (`USER.md`, `MEMORY.md`), которого ещё нет — можно **seed-once** (создать, если отсутствует). Если файл уже есть — не трогать, кроме system-блоков внутри.

Согласовано с идеей puller: `policy: preserve` / `seed-once` для identity и клиентского конфига; `replace` — для кода бота.

## Секреты и продукты

- `.env` и `bots/*/.env` — только владелец / bootstrap с его файлов; обновление кода их не пишет.
- Каталоги продуктов (`~/projects/*`, `*-deploy`, `*-secrets`) — не часть ядра; обновление оркестратора их не трогает.

## Проверка перед выкладкой

Перед массовым обновлением серверов убедиться, что в манифесте/скрипте:

- нет `rsync --delete` на `workspace/` без `--reset-workspace`;
- нет копирования «боевого» `workspace/` из снимка вместо `workspace-seed/`;
- identity-файлы не в списке `policy: replace`.
