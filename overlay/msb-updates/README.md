# msb-updates

Портал обслуживания клиентских ботов. В этом процессе остаются Установщик и прежняя публикация релизов. Новую службу обновлений сюда подключает следующий шаг: маршруты `/v1/updates/` и проверка `allow(installation, 'updates')`.

- Каналы: `core` (зеркало as-is), `ext` (наша обвязка + `compatible_core`)
- Токены индивидуальные на `tg_user_id`
- Установка обвязки на уже стоящий бот снята. Установщик создаёт новый сервер или настраивает уже существующую систему
- Создание сервера: токен Hetzner хранится в клиентской записи, токен Telegram-бота пишется только на сервер
- Настройка уже существующей системы: пользователь присылает имя SSH-входа (по умолчанию root) и вставляет короткий скрипт. Дальше хаб создаёт `msb-admin` и снимает временный sudo. Ключ `msb-admin` снимается только командой `/drop_admin_key`
- IIA Установщик не ставит и не переносит. Старая заявка с `migrate_from=iia` завершается ошибкой `iia_removed`
- `INSTALLER_ADMIN_TG_IDS` обязателен: пустой список — бот никому не отвечает
- Внешний адрес Портала — `PUBLIC_BASE_URL` (`https://aide.win`). Адрес, который Установщик пишет клиенту в `MSB_UPDATES_URL`, задаётся отдельно: `UPDATES_BASE_URL`. Пустое значение установку не продолжает и на `aide.win` само не подставляется
- Схема Портала в Postgres (`PORTAL_DATABASE_URL`): клиент, установка, тикет, сообщение, очередь, права. Без адреса Установщик работает по JSON, как раньше. Таблицы прав пустые
- `ACCESS_POLICY=open` разрешает `support`, `updates` и `backup`. `restricted` пускает только строку в `installation_capabilities`, иначе код `capability_denied`. Создание сервера и первичная настройка через эту проверку не проходят
- `/crm` открывается паролем `CRM_PASSWORD`. Пустой пароль выключает страницу. Сессия в HttpOnly-cookie. Список и карточка читают установки Установщика. Открытые обращения и ответ оператора появляются, когда задан `PORTAL_DATABASE_URL`
- Бот поддержки — отдельный `SUPPORT_BOT_TOKEN`, webhook `/telegram/support`. Пока обращение открыто, следующее сообщение того же человека дописывается в него. Перед записью вызывается `allow(..., 'support')`: при `open` обращение принимается и без установки, при `restricted` нужно право хотя бы на одной установке человека. Закрытие обращения не меняет статус сервера. Форма сайта вызывает тот же `receiveSupportText` с источником `web`, отдельного адреса формы нет
- Ответ оператора ставится в очередь. Повтор того же `operation_id` вторую отправку не создаёт. Неизвестный исход остаётся `uncertain` и сам в повтор не уходит

## Локально

```bash
cp deploy/env.example deploy/env   # или ~/msb-updates/env на хосте
npm install
MSB_UPDATES_DATA=./data node bin/publish.mjs --channel ext --version 0.1.0 \
  --from ../../.msb/bot --compatible-core-min 2026-10-20-bg-web-oc-session.v27.0
MSB_UPDATES_DATA=./data node bin/serve.mjs
```

## Порт для nginx

Слушает `PORT` из env хаба (по умолчанию **8787**, HTTP). Публичное имя Портала — `PUBLIC_BASE_URL`. На клиентский сервер пишется `UPDATES_BASE_URL`, не адрес Портала. Оба параметра меняются без правки кода.

Прокинуть этот порт:

- `/telegram/webhook` — webhook бота-установщика
- `/telegram/support` — webhook бота поддержки
- `/crm` — рабочее место оператора
- `/` и `/v1/*` — веб и API
