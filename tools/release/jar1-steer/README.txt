JAR1 — выборочный code-only выпуск очереди Codex и «Учесть сейчас»

База: d2f2354b4e29357558032744b065e542df33ce19, установленный выборочный
выпуск. Источник релиза должен быть его потомком и содержать только 13 заданных
изменённых и новых bot JS-файлов; отложенные изменения других провайдеров и
OpenClaw в payload не входят. Build экспортирует payload, тесты и оператора из
одного commit, проверяет перечень и хеши. Документированные расхождения старых
README и package.json учитываются в inventory, системные файлы не заменяются.

До применения готовый артефакт проверяется на JAR1 в новом изолированном
каталоге. Root-owned launcher.py проверяет manifest и сетевой namespace службы,
создаёт отдельные network/mount/PID namespaces, поднимает только loopback и
запускает полный разрешённый scoped suite под client в синтетическом HOME.
Сценарии OpenClaw исключены. Native тест запускается только при отдельном netns,
верифицирует CLI 0.166.0 и получает исключительно фиктивную авторизацию и
loopback-модель; хеши wrapper и нативного CLI привязываются к отчёту и повторно
проверяются перед изменением кода. Только подтверждённый report того же manifest
допускает применение. Node/dependencies проверяются против runtime сервера.

Выпуск допускает только добавление шести bot-модулей client:client 0664 и
замену семи файлов с их прежним owner/mode. Перед работой сверяются inventory,
служба, отсутствие активных дочерних процессов, hashes и состояния. При
остановленном боте создаётся закрытый profile snapshot: auth/env, настройки,
контекст и native сессии, SQLite через backup API и quick_check. После startup
активный Codex ID и путь rollout сверяются с запечатанной копией. Это не
утверждение о побайтовой неизменности всех живых SQLite после старта.

При сбое operator возвращает только код и не перезаписывает текущие данные.
Ручной rollback по сохранённому report и backup работает аналогично; новые
файлы удаляются только при совпадении собственного inode и хеша. Повреждение
backup, изменения кода/профиля или неготовность службы блокируют успешную
приёмку. Сам snapshot содержит секреты и личные данные: root 0700/0600, вне Git.

Локальные изолированные проверки: python3 -B -m unittest discover -s
 tools/release/jar1-steer -p 'test_*.py'. Успех них не заменяет запуск sealed
пакета на JAR1 и отдельную живую приёмку в Telegram. Сервисы и настройки вне
бота не меняются; bootstrap, авторизация CLI и автообновления не запускаются.
