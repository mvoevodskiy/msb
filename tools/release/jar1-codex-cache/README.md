# Выборочный выпуск разбивки кеша Codex на JAR1

Пакет берёт runtime и проверки из одного commit. База — фактически
установленный выборочный выпуск `35bf0b6`; его non-OpenClaw inventory и
composite восстанавливаются прежним [сборщиком](../jar1-codex-usage/build.py).
В новый composite попадают шесть изменённых файлов бота и пять Пульта; прочие
пути остаются из проверенной базы. Аккаунты, настройки, базы и сессии не входят
в payload.

1. Из чистого commit запустить `build.py --repo REPO --commit SHA --stage STAGE
   --ccusage-archive ARCHIVE`. Архив pinned ccusage проверяется по SHA-512.
2. Перенести stage на JAR1, распаковать source и composite, подсоединить для
   обоих установленные зависимости бота и выделить изолированный test-home.
   Запустить `launcher.py` с контрольной суммой manifest. Все допустимые общие
   сценарии и Codex проверяются без OpenClaw; две независимые широкие группы
   идут с concurrency 2, остальные — последовательно. Затем выполняются
   проверки breakdown, старых записей, остановки и гибридного composite.
3. После успешных отчётов убрать временный composite, запечатать результаты и
   выполнить read-only планы `deploy.py` и `pult-deploy.py`. Любое расхождение
   runtime, установленной базы, защищённых файлов или службы останавливает выпуск.
4. Применить bot transaction, затем Pult transaction. Обе сохраняют точную
   code-only копию для отката; bot transaction сверяет активную сессию и профиль.
   Pult перезапускает только сборщик, не меняя базу и веб-сессию. При остановке
   Atoll следует явно восстановить **обе** службы `atoll-kamadhoo` и
   `atoll-caddy`: в предыдущем выпуске зависимый Caddy остановился по тайм-ауту.
5. Проверить Telegram `/status`, раздел «Боты» в Пульте и health-check Atoll.

Откат — `pult-deploy.py --rollback` и при необходимости `deploy.py --rollback`
с теми же stage, контрольными суммами и backup; профиль и новые сообщения из
копии автоматически не восстанавливаются.
