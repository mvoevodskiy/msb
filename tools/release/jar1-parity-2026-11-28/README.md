## План, применение и откат

`deploy.py` принимает `--stage`, новый абсолютный `--backup` непосредственно
в `/var/lib/msb-ops/releases`, `--manifest-sha` и `--report-sha` (SHA-256
файла `proof.json`). Без флага действия команда только проверяет
предпосылки. Для `--apply` и `--rollback` оператор добавляет
`--queue-confirmed` после проверки текущего ответа и очереди обоих ботов:
cgroup показывает дочерние процессы, а очередь Telegram хранится в памяти
бота и оператор её проверяет отдельно.

Резервная копия содержит только управляемый код, исходные inode и
хеши имён polling-аккаунтов. Оба instance-unit временно маскируются перед
остановкой. Публикация начнётся после остановки обоих и проверки копии.
Профили сверяются по существующим файлам без копирования сессий.
После запуска обе службы должны появиться в журнале с прежними polling
идентичностями. При частичной публикации оператор автоматически восстанавливает
прежнее дерево и пробует запустить обе службы. Если восстановление дерева
прервано, повторить `--rollback --queue-confirmed` с тем же путём backup.
При недоступности одной службы после восстановления другая запускается
независимо. Если целостность старой версии невозможно подтвердить, обе
startup guards остаются до завершения отката.
