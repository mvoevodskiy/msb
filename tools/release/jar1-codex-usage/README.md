# Выборочный выпуск учёта Codex на JAR1

Код бота и Пульта берётся из одного commit; фиксированный список включает девять
файлов бота и семь файлов Пульта. Установленная база бота восстанавливается из
inventory предыдущего выборочного выпуска, а не из полного дерева HEAD. Сборщик
также запечатывает composite: именно установленная база и девять новых файлов.
Проверки composite и основной scoped gate выполняются в изолированном Linux без
сценариев OpenClaw. `ccusage` 20.0.51 входит как проверенная внешняя зависимость,
не как закоммиченный бинарник. Профили, Pult DB, auth и пользовательские файлы
не входят в payload.

1. Получить публичный `@ccusage/ccusage-linux-x64@20.0.51`; сборщик проверяет
   зафиксированный SHA-512 и извлекает только исполняемый файл.
2. Из чистого commit запустить `build.py --repo REPO --commit SHA --stage STAGE
   --ccusage-archive ARCHIVE`. Перенести закрытый stage на JAR1 в `/var/tmp`.
3. Распаковать `source.tar.gz` в `source`, `composite.tar.gz` в `composite`,
   добавить для обоих только ссылки на установленные bot dependencies. Stage и
   исходники должны быть root-owned и недоступны для записи client; только
   `test-home` выделяется client. Запустить `launcher.py` с SHA manifest.
4. После успешного полного разрешённого gate и feature/composite проверок убрать
   временные ссылки из `composite`, запечатать результаты и выполнить сначала
   read-only планы `deploy.py` и `pult-deploy.py` с SHA обоих отчётов. Любое
   расхождение live inventory останавливает выпуск.
5. Применить bot transaction, затем Pult transaction. Обе сохраняют код для
   отката; bot transaction отдельно проверяет активную сессию и профиль. Pult
   обновляет только код, устанавливает проверенный root-owned ccusage и
   перезапускает только сборщик; web-сессии и Pult DB остаются на месте.
   Проверить свежий снимок и открыть его в Telegram.

Откат: сначала `pult-deploy.py --rollback` с теми же stage/manifest/report и
путём backup, затем при необходимости `deploy.py --rollback` с тем же backup.
Откат не восстанавливает старые auth, настройки, сообщения или native-сессии.
Внешний бинарник остаётся на месте после ручного отката Пульта и не запускается
старой версией сборщика.
