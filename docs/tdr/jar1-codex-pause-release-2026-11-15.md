прошли 1 179 JavaScript и 38 Python проверок, синтаксис 14 файлов и 45 тестов
оператора установки/отката. Девять проверок, требующих root и другого UID,
прошли отдельно в одноразовом Linux-контейнере без сети. В тестовом наборе
осознанно исключены отдельные сценарии OpenClaw; совместимость с ним отдельно
не проверялась. [Машинный отчёт](evidence/jar1-codex-pause-release-2026-11-15/verification.json).

Первый запуск в ошибочном режиме Python не дошёл до тестов. Во второй попытке
два теста записи prompt в файл упали из-за недоступного на запись `/tmp`; после
выделения отдельного tmpfs они прошли точечно, затем весь точный пакет был
прогнан заново. Первый план отказался от пакета с владельцем UID локальной
машины; исправлено только владение временной копии без перехода по ссылкам, и
повторный read-only план подтвердил 14 файлов. Эти случаи не меняли живой код.

## Живая приёмка и ограничения

В Telegram `/status` до и после выпуска/проверок показал Codex, gpt-6.1-terra,
max и тот же префикс беседы. На активном ходе была временно установлена только
тестовая sleep-метка с time guard. `/stop` прервал этот ход; статус и отдельный
ответ сообщили об остановке. Следующее обычное сообщение было заблокировано
паузой. При выборе Claude интерфейс предложил токен; учётные данные не вводились,
текущий Codex не переключился. Тестовая пауза снята существующей кнопкой,
guard подтвердил снятие; форма авторизации закрыта. После этого Codex ответил
на новый короткий запрос в прежней беседе. Тестовые сообщения остались в Telegram
и штатно продвинули контекст до 95%; файлы памяти менять не просили.

Поскольку реальная автономка не включена, её настройки не менялись и тестовые
задачи в рабочий профиль не записывались. Установленный `legacy-dispatch` и
Telegram inbox прогнаны в отдельном одноразовом профиле с фиктивным модельным
ходом и фиктивным Telegram transport: на паузе таймер не сработал, после снятия
сработал один раз и повторный tick его не запустил. Затем отдельный клиент без
повторов отправил одно явно помеченное тестовое уведомление в личный Telegram,
что подтверждено в браузере. Это не проверка исполнения настоящего расписания
или настоящего Codex-хода в рабочем профиле. Собственный тестовый профиль удалён.

Настоящего перехода Claude → Codex и сохранения живой Claude-беседы подтвердить
нельзя: Claude на текущем профиле не авторизован. В изолированных тестах оба
провайдера и их отдельные сессии проверены на фиктивных данных. Если процесс
упадёт до durable promotion таймера, первоначально поставленного при Claude,
этот таймер всё ещё может потеряться; уже допущенный ход автоматически не
повторяется. JSON writer не даёт гарантии сохранения при отключении питания.

После приёмки бот active/enabled, NRestarts=0, test marker отсутствует;
исходный SQLite-lock оставлен на месте. `msb-engine.path` и timer по-прежнему
inactive, прежняя заявка `status` не изменена. Из-за выключенных unit штатное
создание sleep-метки этим выпуском не проверено; системные авто-writers не
включались. Кодекс-сессия, выбранные параметры и подключения сохранены.

## Кодовый откат

Только для этого выпуска: `/var/tmp/msb-pause-recovery-c56f30b` и закрытый backup
`/var/lib/msb-ops/releases/jar1-codex-pause-recovery-c56f30b`.

```sh
python3 -I -B /var/tmp/msb-pause-recovery-c56f30b/deploy.py \
  --stage /var/tmp/msb-pause-recovery-c56f30b \
  --backup /var/lib/msb-ops/releases/jar1-codex-pause-recovery-c56f30b \
  --manifest-sha 552560d05cfe11d5fe414ec09aca7904a9f42db474d92d4f3aa4df28d0c2a7f3 \
  --report-sha 978cc21ff6fb2d84a0d8b21539b1b8d331657ad2fb91521e7b80a316c122f435 \
  --rollback
```

До отката проверить, что нет незавершённого `codexPauseSwitch`, подготовленного
intro handoff и `legacyPendingRun` в фактическом actionRoot: прежний код их не
разрешает автоматически. Откат возвращает только код, не историю Telegram,
новые результаты и не содержимое профиля. При `guard.pending` не снимать mask
вручную до сверки защищённой копии и инодов.
