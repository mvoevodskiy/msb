# Перенос сведений старой установки OpenClaw

Это отдельная операторская операция для миграции старого сервера. Она **не**
устанавливает и не запускает OpenClaw, не считывает авторизацию или переписку,
не удаляет старые данные и не доказывает, что Telegram-канал отвечает. На JAR1
эту команду без отдельного поручения не запускать.

`msb-engine adopt-legacy` требует остановленного старого стека: его path/timer
должны быть отключены, старые oneshot-сервисы и transient sandbox отсутствовать,
а старый `/run/jarvis-engine/lock` — существовать и быть доступным для захвата.
Команда проверяет эти условия дважды и удерживает старую и новую блокировки.
Оператор должен также исключить параллельный ручной запуск старого setup: он не
обязательно соблюдает блокировку. Не останавливать и не маскировать службы
автоматически ради одной этой проверки.

Из проверенных root-файлов копируются только факты установки, настройки и
отдельный признак выключения. Файлы публикуются в порядке pending → off → setup
→ marker. Повтор проверяет исходные факты и не перезаписывает другую установку.
Старые файлы, включая root-корзину и иные данные, остаются на месте.
Связь старого installation ID с текущей службой не подтверждается одними UID и
именем unit: до отдельной проверки канала готовность остаётся `unknown`, и
переключение, которое усыпит последнего бота, запрещено.

Если операция прервалась, повторять её можно только с теми же исходными фактами.
При повреждённом, изменившемся или отсутствующем источнике команда откажет,
сохранив `openclaw-adoption.pending`; запуск OpenClaw через этот механизм и
автовосстановление при этом приостановлены. Не удалять pending вслепую: сначала
сверить источник и состояние с проверенной резервной копией, затем отдельно
решить восстановление. Операция не включена в автоматический bootstrap/migrate.

`bootstrap/install.sh` сохраняет каталог старого системного состояния
`/var/lib/jarvis-engine` и временную блокировку `/run/jarvis-engine`: первый
может включать root-корзину, а вторая нужна для проверки переноса. Блокировка
находится в `/run` и исчезнет при перезагрузке; её наличие не доказывает, что
старые службы остановлены. Это сохранение не делает bootstrap миграцией: он
по-прежнему меняет сервисы и другие системные файлы. На существующем сервере
не запускать его без отдельного плана и проверенной резервной копии.

Проверки выполняются на временных файлах:
`python3 -B -m unittest discover -s usr-local-lib/msb-engine/tests -p 'test_legacy_*.py'`.
Реальная совместимость с PID 1, остановкой старых служб и каналом требует
отдельного изолированного Linux-стенда и не подтверждается этими тестами.
