# Аудит open-core — 20 ноября 2026

## Результат и область проверки

Найдены и исправлены пять подтверждённых дефектов в Codex и общих маршрутах
Telegram, очереди и планировщика. Каждый исправлен отдельным коммитом с
описанием сценария, старого поведения, затронутых связей, проверок и отката.
Ещё один коммит исправляет устаревшее ожидание в тестовом helper.

Статус исправлений: **verified-isolated**. Проверки использовали настоящий
новый обработчик и, где необходимо, отдельные процессы, но подставные Telegram,
STT и native protocol peer. Живая приёмка Telegram/JAR1 не проводилась.
Это аудит перечисленных сценариев, а не доказательство полной эквивалентности
всего старого и нового ядра или исчерпывающий аудит безопасности.

## Исправленные дефекты

### P1 — остановка Codex оставляла native app-server работающим

Прямой дочерний процесс ядра — shim — завершался на SIGINT раньше native
app-server с отдельными pipe. Ядро получало событие close и отменяло дальнейшую
эскалацию. Очередь могла освободиться, хотя native процесс продолжал работу.
Изолированное воспроизведение фиксировало heartbeat после возврата ядра.

Теперь foreground Codex shim принимает SIGINT/SIGTERM, передаёт AbortSignal
через адаптер и ждёт завершения native дочернего процесса. Abort закрывает
ожидающие RPC/readiness и исключает поздний terminal response и сохранение
сессии. Существующая очистка EOF → TERM → KILL и защита истории сохраняются.

[Исправление 0687882](https://github.com/SergeyKoleda/Jarvis/commit/06878826ebb2ba724b4a63a86240cc5bf4c4bffa).
Основная проверка: [codex-steer-stop.test.mjs](../../.msb/bot/tests/codex-steer-stop.test.mjs)
с отдельным процессом, игнорирующим мягкие сигналы. Старый эталон: строки
19552–19585 указанного readable blob. App-server steering — принятый новый
транспорт, поэтому старый механизм не переносился механически.

### P1 — отказ статуса очереди терял последующие сообщения и таймеры

Inbox заранее объединял и удалял соседние элементы. Если статус первого
элемента не отправлялся или не обновлялся, последующие сообщения уже не имели
самостоятельного места в очереди. Одноразовые таймеры могли считаться
использованными без запуска объединённой работы.

Объединение теперь возможно только после подтверждённого статуса первого
элемента. Если статус отсутствует, ещё ожидается или завершился ошибкой,
первый элемент проходит обычный lifecycle отдельно; хвост остаётся в FIFO.
Отказ обновления существующего статуса объединённого хода сохраняет прежнюю
опору для ответа. При задержанном статусе reply «стоп» по-прежнему достигает
зарегистрированного хода и сохраняет следующее сообщение.

[Исправление 3509608](https://github.com/SergeyKoleda/Jarvis/commit/3509608c4a5f0ca68b46c1d8f3ef7c31e59f2015).
Проверки: [legacy-timer-dispatch.test.mjs](../../.msb/bot/tests/legacy-timer-dispatch.test.mjs)
и [inbox-lifecycle.test.mjs](../../.msb/bot/tests/inbox-lifecycle.test.mjs).
Четыре исходных отказа и гонка reply-stop воспроизведены до исправления.
Старый эталон: 110249–110324 и 119450–119470.

Политика одной попытки для непредставленного первого таймера не менялась:
исправление сохраняет последующую работу и не вводит автоматический повтор.
При задержанном статусе соседние сообщения могут выполняться раздельно.

### P2 — завершение планировщика не отменяло активный интервал

`scheduler.stop()` ожидал отдельные dispatch-маршруты, но интервал учитывался
только флагом busy и не получал shutdown signal. Главный процесс мог перейти
к выходу, пока interval turn ещё работал.

Теперь stop отменяет активный интервал и ждёт полного taskTick. Незавершённая
попытка не получает запись об успешном окончании и сдвиг следующего запуска.
Если модель уже завершилась, а shutdown пришёл во время уведомления,
подтверждённый результат и новое расписание сохраняются.

[Исправление 13817d3](https://github.com/SergeyKoleda/Jarvis/commit/13817d34ebc76b67b19b5bcbb09f20266d8376a5).
Проверка: [autonomy-shutdown.test.mjs](../../.msb/bot/tests/autonomy-shutdown.test.mjs).
Старый эталон владения дочерними процессами: 20399–20416 и 122452–122492.
Семантика chat `/stop` и принятое отсутствие автоматического replay не менялись.

### P2 — ошибка получения голосового блокировала всю очередь

Кнопка «Учесть сейчас» переводила очередь в неопределённое состояние, когда
Telegram не предоставлял аудиофайл, хотя STT и отправка корректировки ещё не
начинались. Следующие сообщения останавливались вместе с неудачным голосовым.

Отказы getFile, отсутствующий file_path, HTTP, transport, timeout и чтение
тела до `transcribeVoice` теперь имеют отдельный тип ошибки. Завершается
только соответствующий голосовой элемент. Abort остаётся приоритетным,
а исходные URL ошибок с токеном бота не выводятся пользователю.

[Исправление 266ff26](https://github.com/SergeyKoleda/Jarvis/commit/266ff26dccae771e4ae123e1962201981711fbb7).
Проверка: [steer-telegram.test.mjs](../../.msb/bot/tests/steer-telegram.test.mjs).
Тесты подтверждают ноль STT/correction calls при таких отказах, снятие кнопки
и последующий запуск текста. Отдельная проверка сохраняет блокировку при
потерянном ответе уже запущенного STT, без повторной отправки аудио.
Старый эталон: 119934–119977 и 110273–110285.

### P2 — форматирование повреждало HTML внутри примеров кода

Последовательные проходы защиты HTML, fenced и inline code вкладывали
служебные placeholder друг в друга. После одного прохода восстановления
Telegram мог получить внутренний NUL-token вместо исходного примера.

Рендерер теперь защищает внешние code regions в порядке исходного текста.
Обычные блоки и inline code сохраняют буквальные HTML-теги. Для распознанного
Telegram HTML-блока закрывающий fence ищется вне полных raw code/pre regions:
тройные обратные кавычки внутри примера не повреждают следующий JS-блок.

[Исправление 93bfed9](https://github.com/SergeyKoleda/Jarvis/commit/93bfed9099333c21e006117527fb3085c4b85306).
Проверка: [response-delivery.test.mjs](../../.msb/bot/tests/response-delivery.test.mjs).
Старый эталон `_zA/Hu`: 3100–3159. Это исправление существующего набора
форматирования; полная грамматика Markdown не добавлялась.

## Границы и дальнейшая приёмка

- **external-condition:** один существующий native Codex тест пропущен,
  поскольку не задан `MSB_TEST_CODEX_NATIVE` с изолированной подходящей
  сборкой CLI. Проверка core/shim/дочернего процесса с protocol peer прошла.
- **needs-evidence:** живая работа с Codex, Telegram и принятие готового
  релиза на JAR1 остаются отдельными этапами. Этот перенос не является deploy.
- **needs-evidence:** обработчик `/undo` в
  [bot.mjs](../../.msb/bot/src/telegram/bot.mjs) явно сообщает, что автоматическая
  отмена правок пока не подключена. Для этого маршрута нужна отдельная сверка
  со старым ядром и проверка отката файлов; эти пять исправлений его не реализуют.
- **accepted-difference:** неоднозначный ответ STT/steer не повторяется
  автоматически; per-bot env и fencing выбранных native sessions сохранены.
- Проверены существующие связанные регрессии Claude и переключения
  провайдера. Отдельные доработки Claude не выполнялись.
- OpenClaw не развивался, не включался и отдельно не проверялся, согласно
  текущему ограничению проекта.

Общий откат отдельного исправления — `git revert` соответствующего коммита
Jarvis. Миграций пользовательских данных в этих изменениях нет. Для выпуска
нужны обычные export/startup/live acceptance процедуры из release pipeline.
