# MCP

[Кнопка в Telegram](../telegram/routes/workspace.mjs) передаёт снимок
выбранного движка в [каталог](catalog.mjs), затем отображает полученные
имена и транспорты в [экране](../telegram/screens/workspace.mjs).

[Claude](claude.mjs) читает пользовательский .claude.json и для папки
подставляет доступные состояния из mcp-status.json текущего бота. Отсутствие
пользовательского файла означает пустую конфигурацию. Ошибка чтения или
повреждённый файл дают ошибку экрана. Наличие записи не проверяет соединение.

[Codex](../../../../overlay/bot/ext/codex-mcp.mjs) читает пользовательский
слой config/read через приложение Codex. Слой сверяется с CODEX_HOME.
Модель, авторизация и подключение к настроенным MCP-серверам для этого
вызова не нужны. Проектные слои и значения заголовков, окружения и
аргументов остаются внутри адаптера.

[OpenClaw](openclaw.mjs) читает собственный mcp list --json, повторяя
неудачный вызов один раз. URL в списке выводятся без учётных данных,
параметров и фрагмента. Ошибка CLI и успешно прочитанный пустой список
имеют разные экраны.

[Кнопки карточек](reference.mjs) привязаны к движку и пути к конфигурации.
Старые текстовые кнопки открывают только одноимённую карточку Claude.
Прежний запрос не перерисовывает экран после перехода по другой кнопке.
Если движок переключили в другом чате, результат чтения прежнего движка
отбрасывается.

[Тесты каталога](../../tests/mcp-catalog.test.mjs) и
[проба Codex 0.166](../../tests/reference/mcp-native-0.166-protocol.json)
покрывают чтение.

[Форма](../telegram/forms/mcp.mjs) принимает один ключ и удаляет сообщение
с валидным вводом, если Telegram позволяет. [Запись](managed.mjs) хранит имя
шаблона и ссылку на ключ в состоянии текущего бота. Сам ключ хранится в его
.env. При настройке того же сервиса во втором движке используется отдельное
имя ключа с суффиксом движка, чтобы первый продолжал работать со своим
значением. Кнопка «Удалить» у записи бота убирает подключение и сохраняет ключ.

[Подготовка запуска](launch.mjs) берёт значение по этой ссылке только из .env
выбранного бота. Claude получает временный конфиг со ссылками на переменные
окружения, Codex — аргументы со ссылками через [адаптер](../../../../overlay/bot/ext/codex-mcp-launch.mjs).
В обычном ходе Claude в существующий --allowedTools добавляются разрешения
для MCP из пользовательского конфига и активных записей бота. Явный список
инструментов сохраняет свои границы. Имена с разделителями CLI не формируют
автоматическое разрешение.
[Служебное имя Codex](../../shared/codex-mcp-name.mjs) стабильно в профиле
бота. Обычная нативная запись с именем apify или supadata сохраняет свой
адрес и заголовки рядом с записью бота, даже если её добавили после
чтения конфига. При двух одинаковых названиях список помечает запись
бота, а карточка показывает её фактическое имя инструмента. Если служебное
имя уже занято, форма и подготовка запуска пропускают такой шаблон.

[Удаление унаследованной записи](native-removal.mjs) хранится в состоянии
выбранного бота с привязкой к движку и физическому файлу профиля. Кнопка
сразу убирает строку из каталога. Исходный конфиг и его ключи остаются
доступны другим ботам. Если симлинк профиля сменится во время чтения,
устаревший ответ Codex отбрасывается.

Следующий обычный ход и /compact исключают указанное имя в этом профиле.
В Claude запрет передаётся на один запуск и дополняет правила пользователя
и проекта. Codex проверяет пользовательский слой перед запуском и
накладывает флаг отключения на существующее имя. При смене файла
профиля после подготовки оба запуска останавливаются. При повторном
добавлении шаблон снова использует ключ этого бота. В Claude активная запись
бота замещает старое имя. В Codex она подключается под своим именем рядом
с выключенной записью.

Исключение действует на имя, используемое движком. Одноимённая проектная
запись в запуске этого бота попадает под то же исключение. Приоритет
внешних управляемых настроек остаётся у CLI. Если запись Codex исчезла
внешней правкой между проверкой и загрузкой конфига, CLI может остановить
этот запуск. Следующий запуск пропускает уже отсутствующее имя.

[Формы](../../tests/mcp-setup.test.mjs) и [запуск](../../tests/mcp-launch.test.mjs)
проверены через реальные обработчики с тестовыми бинарниками.
[Проба Codex](../../tests/reference/mcp-native-0.166-transport.json) подтвердила
вызов инструмента. [Проба Claude](../../tests/reference/mcp-native-claude-transport.json)
также подтвердила вызов на двух тестовых профилях с локальным MCP и ответом
модели из тестовой заглушки.
[Контракт](../../tests/reference/parity-mcp-contract.txt) хранит исходные
доказательства. Вручную созданная запись, которая заняла точное служебное
имя в интервале между чтением и запуском, по-прежнему подчиняется правилам
слияния Codex.

## Подключение из ответа агента

[Инструкция ADD_MCP](install-protocol.mjs) описывает HTTPS с заголовками
и stdio с командой и аргументами. [Финализация Telegram](../telegram/install-markers.mjs)
сначала обрабатывает навык, затем [подключение MCP](response-markers.mjs).
Бот обрабатывает первый блок, удаляет последующие и подставляет прежний
текст результата до вывода плана и записи дневника. Общий флаг
`SKILL_INSTALL_ENABLED=0` отключает запись. Оборванный JSON скрывается,
а закрывающий тег внутри JSON-строки остаётся частью значения.

[Реестр](managed.mjs) записывает подключение в профиль бота и движка,
который сформировал ответ. В state.json остаётся ссылка. Адрес, заголовки,
команда и аргументы хранятся в [закрытом файле](custom-config.mjs) с правами
0600 в каталоге бота `mcp-config/`. Повтор по имени заменяет запись.
Если то же имя было унаследовано из нативного пользовательского файла,
[исключение](native-removal.mjs) скрывает его только у этого бота. После
«Удалить» унаследованная строка у этого бота остаётся скрытой. Файл и
подключение соседа остаются доступны. Для Codex чтение фактического слоя
проверяет занятость служебного имени до сохранения.

На следующем обычном ходе [запуск](launch.mjs) добавляет конфигурацию
в существующий временный файл Claude или во [временный профиль Codex](../../../../overlay/bot/ext/codex-mcp-custom.mjs).
В параметрах Codex передаётся имя профиля. Общий config.toml остаётся
источником нативных настроек. После хода ядро освобождает временные файлы.
Запись и отмену до публикации состояния проверяет [сквозной тест](../../tests/mcp-marker.test.mjs).
Возможность запуска Codex проверяет [изолированная нативная проба](../../tests/reference/mcp-native-marker-0.166.mjs).

## Шаблоны OpenClaw

[Форма](../telegram/forms/mcp.mjs) сохраняет ключ бота, затем
[запись](openclaw-setup.mjs) сверяет физический конфиг уже работающего
локального Gateway. Для записи пути OpenClaw задаются явно в каталоге бота.
Путь в ответе Gateway должен совпасть с файлом выбранного профиля. Шаблон
передаётся через временный файл 0600 в нативный config set. Подтверждение
появляется после повторного чтения регистрации через тот же Gateway.
Соседние настройки и ключи Claude/Codex остаются в своих профилях.

При сбое ключ остаётся в .env бота, а сообщение сообщает о недоступном
подключении. Каталог показывает данные нативного CLI, поэтому наличие ключа
само по себе не добавляет строку MCP. Достижимый OpenClaw UI по-прежнему
содержит Add и Back. [Проверки формы](../../tests/openclaw-mcp-setup.test.mjs).
[Нативная проба](../../tests/reference/openclaw-native-mcp-2026.9.5.mjs) проверяет
запись, использование инструмента в той же сессии и смену Gateway.
