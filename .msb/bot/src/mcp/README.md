# MCP

[Кнопка в Telegram](../telegram/routes/workspace.mjs) передаёт снимок
выбранного движка в [каталог](catalog.mjs), затем отображает полученные
имена и транспорты в [экране](../telegram/screens/workspace.mjs).

[Claude](claude.mjs) читает пользовательский .claude.json и для папки
подставляет доступные состояния из mcp-status.json текущего бота. Отсутствие
пользовательского файла означает пустую конфигурацию. Ошибка чтения или
повреждённый файл дают ошибку экрана. Наличие записи не проверяет соединение.

[Codex](../../../../overlay/bot/ext/codex-mcp.mjs) читает пользовательский
слой config/read через приложение Codex. Слой сверяется с CODEX_HOME.
Модель, авторизация и подключение к настроенным MCP-серверам для этого
вызова не нужны. Проектные слои и значения заголовков, окружения и
аргументов остаются внутри адаптера.

[OpenClaw](openclaw.mjs) читает собственный mcp list --json, повторяя
неудачный вызов один раз. URL в списке выводятся без учётных данных,
параметров и фрагмента. Ошибка CLI и успешно прочитанный пустой список
имеют разные экраны.

[Кнопки карточек](reference.mjs) привязаны к движку и пути к конфигурации.
Старые текстовые кнопки открывают только одноимённую карточку Claude.
Прежний запрос не перерисовывает экран после перехода по другой кнопке.
Если движок переключили в другом чате, результат чтения прежнего движка
отбрасывается.

[Тесты маршрута](../../tests/mcp-catalog.test.mjs) и
[проба Codex 0.166](../../tests/reference/mcp-native-0.166-protocol.json)
покрывают чтение. [Контракт](../../tests/reference/parity-mcp-contract.txt)
хранит старый исходный эталон и границы этапов настройки, удаления и
обработки ADD_MCP. Пока эти этапы отсутствуют, каталог проверяется локально.
