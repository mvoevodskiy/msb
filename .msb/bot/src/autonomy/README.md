# Автономка

[← Вход ядра](../main.mjs) · [Исполнение](../agent/README.md) ·
[Telegram](../telegram/README.md#callback-маршруты)

`store` сериализует read/modify/write через общий [file lock](../../shared/file-lock.mjs).
Scheduler перечитывает кандидата до запуска, а по завершении условно сохраняет
только поля результата неизменённой задачи. Новый/удалённый/отредактированный
вход не затирается старым снимком; lock не удерживается во время модели.
[persistence regression](../../tests/autonomy-store-concurrency.test.mjs) проверяет
также независимые процессы. [Контракт old→new](../../tests/reference/parity-autonomy-contract.txt). `saveAllTasks` — явная замена всего списка, не API
будущих toggle/delete; их read/modify/write должно оставаться в store transaction.
Lock сериализует запись JSON, не резервирует выполнение задачи между несколькими
scheduler-процессами. При изменении задачи во время хода CAS отбрасывает старый
результат; это сохраняет правку, но не даёт гарантии однократных внешних эффектов.

Базовые интервальные задачи используют общий `runAgentTurn` и состояние бота.
Данные — `<profile.root>/autonomy` либо явно заданный `AUTONOMY_DIR`.

| Задача | Файл → функция |
|---|---|
| Разобрать сообщение «каждые N часов …» | [store.mjs](store.mjs): `tryParseScheduleMessage` |
| Прочитать/сохранить задачи | [store.mjs](store.mjs): `listTasks`, `addTask`, `saveTaskResult` (полная замена — только явный `saveAllTasks`) |
| Выполнить наступившую задачу и сохранить `runs.jsonl` | [scheduler.mjs](scheduler.mjs): `startScheduler`, внутренний `runTask` |
| Запустить сохранённый таймер | [legacy-dispatch.mjs](legacy-dispatch.mjs) → [очередь Telegram](../telegram/inbox.mjs) |
| Не начинать фоновый ход одновременно с `/compact` | [session-operation.mjs](../agent/session-operation.mjs): `trySessionOperation` |
| Прочитать журнал и подготовить страницы истории | [history.mjs](history.mjs): `readRecentRuns`, `historyPages` |
| Список, карточки и настройки UI | [screens/autonomy](../telegram/screens/autonomy.mjs), [routes/autonomy](../telegram/routes/autonomy.mjs) |

`main` запускает scheduler; его `stop()` снимает таймеры. Отдельная отмена уже
начатого фонового `runAgentTurn` этим методом не реализована.
У сохранённых таймеров есть список, карточка, включение, выключение и удаление.
[Хранилище](./legacy-timers.mjs) читает schedules.json рядом с папкой сессий,
как в старом ядре. [Экран](../telegram/screens/legacy-timers.mjs) показывает
записи once, daily и weekly. [Проверки](../../tests/autonomy-timers.test.mjs)
идут через [Telegram callback](../telegram/routes/autonomy.mjs).
[Планировщик](./scheduler.mjs) проверяет расписания в часовом поясе владельца
и передаёт наступивший таймер в [очередь](../telegram/inbox.mjs) для сохранённого
чата. Очередь резервирует место до записи lastRunAt. Запись разового
таймера сразу выключается. Статусы, typing, итог и отмена используют обычный
ход Telegram. Ошибка записи снимает резерв и допускает следующий тик.
Пауза бота учитывается по прежнему engine/sleep.<botId>.
[Проверки запуска](../../tests/legacy-timer-dispatch.test.mjs).

### Разовое напоминание из разговора

[Системная инструкция](./reminder-protocol.mjs) передаётся Claude или Codex при
включённой автономке и сохранённом чате владельца. [Обработчик ответа](../telegram/reminder-markers.mjs)
разбирает SCHEDULE_TASK в итоговом ответе. [Хранилище](./reminder-store.mjs)
сохраняет разовую задачу в actions.json рядом с папкой сессий. После записи
появляется подтверждение. [Список и карточка](../telegram/screens/reminders.mjs)
используют существующее меню «Задачи», включая выключение и удаление.

[Отправка](./reminder-dispatch.mjs) учитывает сохранённый чат владельца и
[флаги автономки](./reminder-policy.mjs). Она записывает попытку до запроса
Telegram, чтобы следующему процессу не досталась та же запись. Сбой между
записью попытки и отправкой может привести к пропуску напоминания. Текст
отправляется напрямую, без вызова модели. [Журнал](./reminder-runs.mjs)
читается меню «История», /autostatus и сборщиком Пульта в профиле бота.

[Изолированные проверки](../../tests/one-shot-reminder.test.mjs) идут через
рабочий обработчик Telegram, планировщик и синтетические CLI. Нативный cron
OpenClaw, остальные виды действий и общие лимиты старого цикла относятся к
следующим этапам. Текущий локальный сценарий проверен в профиле без сети.

### Допуск разовых напоминаний

[Проверка допуска](./reminder-admission.mjs) учитывает сохранённую паузу
после ошибок, [общий журнал](./box-runs.mjs), остаток Claude из [сохранённого
снимка](../agent/claude-quota.mjs) и ограничения расходов владельца и самого действия. Общий день
считается по UTC, личный резерв — по часовому поясу владельца. Действующие
записи интервалов участвуют в счётчике запусков. Цена и входные токены
учитываются, когда они есть в журнале.

Причина отказа сохраняется до уведомления. История показывает отказ и
пропуск отдельно от ошибки отправки. Старый общий предел рассчитан на
завершённые записи журнала. При одновременном запуске двух ботов решение
может опираться на один и тот же снимок. Сохранённый снимок Claude не
применяется к Codex. Источник квоты Codex в Пульте работает отдельно.

[Проверки допуска](../../tests/reminder-limits.test.mjs) используют старые
форматы журналов, тестовый Telegram и отдельные профили.

### Изменение пределов из разговора

[Протокол](./limit-protocol.mjs) задаёт прежние пять ключей и диапазоны. После
успешного обычного ответа владельцу [обработчик](../telegram/limit-markers.mjs)
передаёт значение в [существующий .env бота](../env/store.mjs). Допуск
разовых напоминаний видит новое значение без перезапуска и продолжает считать
дневные деньги, ходы и токены по общему журналу сервера. Резерв и число
включённых действий читают существующие проверки. `/cost` использует отдельную
историю и лимит владельца.

Ноль требует подтверждения [кнопками](../telegram/limit-confirmation.mjs) в том
же чате и теме. [Привязка](./limit-control.mjs) сохраняется до показа кнопок,
переживает перезапуск и расходуется один раз. Кнопка «Оставить» закрывает
свой вопрос. Перед записью проверяется текущий локальный маршрут. Снятие
одного предела оставляет остальные проверки действующими. [Тесты](../../tests/autonomy-limit-control.test.mjs)
используют два временных профиля и тестовый Telegram.

### Общая пауза текущего бота

[Обработчик ответа](../telegram/pause-markers.mjs) распознаёт просьбу владельца
поставить фоновые задачи на паузу или возобновить их. [Хранилище паузы](./owner-pause.mjs)
записывает старый файл autonomy/STOP в профиле текущего бота. Планировщик
прерывает активный локальный интервальный ход и ждёт возобновления.
Разовые напоминания, которые ещё не начали отправляться, сохраняют своё время.
Общая пауза сервера продолжает действовать независимо от этой команды.

Сохранённые таймеры работают до отдельного [подтверждения](../telegram/pause-confirmation.mjs).
Возобновление возвращает таймеры с отметкой disabledBy=stop. Вручную выключенные
таймеры сохраняют своё состояние. /stop в Telegram по-прежнему прерывает обычный
ход. Старые задания OpenClaw с собственным cron требуют отдельного маршрута,
поэтому при наличии таких записей ответ указывает на неполную остановку.

[Проверки](../../tests/autonomy-pause.test.mjs) проходят через существующие
ответ и кнопки Telegram, два прохода планировщика и временные профили.

Часть действий карточек задач пока не подключена. Сохранённые autonomy rights
ещё не задают отдельные права исполнения.
Журнал интервалов сохраняет существующие поля независимо от CLI. Прямые
напоминания пишут прежнюю схему ts/actionId/status с нулевой стоимостью.
`/autostatus [N]` ограничивает выборку до 1–50 строк, по умолчанию 10.

Проверки: [paths-state](../../tests/paths-state.test.mjs) включает парсер расписания,
[menu-handlers](../../tests/menu-handlers.test.mjs) — сохранённые настройки,
[autonomy-history](../../tests/autonomy-history.test.mjs) — история и её границы.
Эталон: [CONTRACT-autonomy](../../vendor/CONTRACT-autonomy.md).
