Contract:
- Work for the same captured bot/chat/topic, Codex profile and base workspace;
  preserve strict Claude-only routing and the existing native Claude path.
- On natural completion or at the old cap, obtain a bounded summary through the
  existing introduction conversation. Keep only facts and preferences the owner
  permits storing. Do not store credentials, temporary/test instructions or facts
  the owner asked not to retain. Model-produced output must be validated; failure
  cannot be presented as a completed or accurate profile.
- Safely preserve existing owner content: add permitted facts to USER.md and/or
  MEMORY.md, whose normal context loader reads them. Never blindly rewrite or
  replace existing SOUL.md/CLAUDE.md. Publish recoverably and avoid duplicates on
  retry; mark introduction completed only after the required profile is durable.
- Preserve the introduction's native Codex conversation and relevant ledger
  metadata. Make it active only when it belongs to the captured Codex provider,
  profile and workspace and no newer/ordinary session supersedes it. Otherwise
  retain existing active/parked sessions and make genuine history available for
  explicit selection. Respect /newtask vs /clear, project/provider changes,
  per-provider sessions, sessionEpoch and late-result fences.
- On reaching the cap, retain the original prepared input and, after successful
  finalisation, run it once through the existing ordinary turn and Telegram
  delivery pipeline. Do not call media transcription/download a second time,
  bypass ordinary actions/footer or change the service card's existing role.
- Keep a private, scoped, recoverable pending input during the transition. After
  a restart a request known not to have started may be resumed; once execution
  could have caused side effects, do not replay it automatically. /stop and
  explicit reset must not revive a cancelled request. Report finalisation failure
  without a false success or discarding the user input.
- Check natural completion and 8->9, text and synthetic media, owner files,
  same/different provider/profile/project, existing ordinary session, switch,
  /stop,/newtask,/clear, write/model failures, crash boundaries and duplicate
  delivery. Verify with isolated fixtures and actual JAR1 Linux release tests;
  live acceptance must not pollute the owner's profile with test facts.
