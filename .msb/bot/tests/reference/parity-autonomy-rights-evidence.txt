The old UI described extra client rights for eligible background tasks, while
read-only tasks retained their own bounds. The guard also checked capabilities,
opt-in, a noninteractive sudo probe and guard settings; the flag alone did not
add a shell tool. This is not proof that current Codex has an equivalent guard.

In the inspected new-core runtime, autonomyRights is stored and displayed by
the Telegram route/screen but is not consumed by the simple tasks.json interval
scheduler or the ordinary Codex adapter. The interval calls runAgentTurn with
autonomy:true; its ordinary Codex shim builds exec with
  --sandbox danger-full-access
  -c approval_policy="never"
The same settings are selected with autonomyRights false or true. This describes
CLI arguments, not proof of root/sudo, actual OS access or effects on JAR1.
Systemd and OS permissions remain separate. The accepted c56f30b source has
the same relevant ordinary Codex adapter, shim and scheduler path; that is not
a live server check.

Separately saved Codex prompt actions use another adapter with an ephemeral
read-only CLI sandbox, shell_tool disabled and a scoped workspace MCP tool set.
Read-only CLI mode alone does not prove every MCP operation is read-only. Do not
conflate these actions with the simple interval or claim either matches the
old privileged guard in full.

Local proof: `node tests/reference/probe-codex-interval-rights.mjs` from .msb/bot
runs the real scheduler -> core turn -> shim -> owned fake Codex, with a fake
ChatGPT profile and temporary workspace, for both toggle values. It inspects
argv, not actual file access or privilege escalation. The selected existing
saved-action check is run via tests/fixtures/saved-codex-without-engine-dispatch.mjs
with --experimental-test-module-mocks and a name filter. Both passed on local
Node 26 and isolated Linux arm64 Node 22.23.2; Linux had no network, and the
unrelated dispatcher was mocked. An initial probe failed because its synthetic
bin directory was absent; creating it fixed the fixture, not product behavior.
No real credentials, model, filesystem target, JAR1 or OpenClaw was exercised.
On 16 November the owner chose to retain the existing access of simple Codex
intervals for now. Do not expand or restrict their existing CLI arguments,
permissions or settings; retain the permission policies of neighboring saved
actions while fixing pause admission.
