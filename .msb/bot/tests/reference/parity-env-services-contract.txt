Адаптация по фактической ответственности
Каталог содержит19прежних key/label и hintflags. Не выдавать старые длинные
описания API/Haiku scoring/Voyage-memory или встроенные tools за работающие
backends нового ядра; catalogpresence не доказывает эти интеграции. Старые
Anthropic always-search/check_capabilities/cleanEnv/SERVICES.md claims не следуют
из нового пути и не переносятся как факты. Prompt передаёт имена/метки/configstatus,
не values, authуспех или обещание работы API. Существующий неподтверждённый текст
«Все ключи доступны в Bash через $ИМЯ» тоже не подходит всем поддержанным именам:
1A существует в process env, но $1A — positionalparam1 + A. Native CLI может
фильтровать shell env. Metadata не обещает универсальную shell expansion.

Deepgram требует адаптации, не буквального process-only копирования.
В новом ядре реальным выбором STT владеет src/media/stt.resolveSttConfig:
process→perbot→shared, explicit-empty blocksfallback, чтение не меняет processenv.
На JAR1 в startup env нет DEEPGRAM_API_KEY/STT_COMMAND (прочитаны только bool);
предыдущие реальные voice проверки прошли через существующий filefallback.
Поэтому Deepgram keypresence брать из того же resolver, не новой копии lookup.
Command+key означает лишь ключ задан, не выбор Deepgram; command-only ключа нет.
STT_NOT_CONFIGURED→ключа нет. Иная ошибка чтения→фиксированный unknownstatus,
без err.message/filename/value и без срыва обычного текстового хода.
Для остальныхMG отражать именно processenvpresence, не отсутствие ключа вообще
во всех возможных loaders. Generic globalenvloader/migration/authchanges нет.

Custom metadata остаётся на принятом perbot пути. Кроме knownMG/protected,
сохранять исключение внутренних PULT_* quicksettings: это конфигурация панели,
не новая service capability. Globalcustom visibility остаётся отдельным аудитом.
Реальные serviceAPI, полная oldtool check_capabilities и recipes/другие backends
не считаются восстановленными этим узким metadata этапом.
