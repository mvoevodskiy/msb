Before this fix, an ID input had no handle and accidentally matched any earlier
old-shaped record with no handle. The wrong record could be enabled and the
requested source not added. This fix matches present IDs/handles first, keeps
the legacy handle-prefixed ID match, and only re-enables explicit false. Missing
or null enabled is active in the current poller, unlike old falsy semantics.
Multiple matching records are preserved and reported as ambiguous.

Important remaining parity gap: for an input handle with no exact saved match,
open-core retains its existing fallback by display name. A display name is not
proof of identity, so this can still match a different channel; conversely an
unresolved handle and channel ID for the same channel may produce duplicates.
The old core resolved before comparing, while this stage does not perform a
network request or claim full equivalence. Legacy handle: values are accepted
for lookup as before, but their polling compatibility is not established.
