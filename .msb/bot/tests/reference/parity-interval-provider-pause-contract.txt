Interval Codex pause and provider transition — RED → GREEN

Old reference: git show 73aa9e7e850bad7ac1ea8a8091d086ecbfd47a11 | nl -ba.
Lines 3785–3803 describe the per-bot sleep marker; 109826–109879 show the
old general admission gate. The old source does not contain the current Codex
provider or the new tasks.json interval route, so it cannot prove exact Codex
semantics. The accepted new-core contract keeps a selected Codex asleep and
preserves each provider's conversation during switching.

The original RED probe in commit 1f3f756 used the actual Telegram
provider-selection callback, a fake CLI login status held at a barrier, the
actual interval scheduler and agent router, and a fake model runner. Selection
starts while Claude is active and no marker exists; after the ingress gate, a
new sleep marker is written. The interval passes its Codex check while Claude
is still selected. Provider selection then restores Codex and its parked test
session; the interval enters the fake Codex runner, preserves the marker but
advances nextAt. This is RED, not evidence that JAR1 had this interleaving.

The RED probe used temporary files, fake auth/CLI status, fake Telegram and
fake model. CLI installation was mocked; no real provider, network, JAR1 or
OpenClaw behavior was exercised. RED was reproduced on local Node 26 and
isolated Linux Node 22.23.2. The first Linux attempt used a noexec temporary
mount; the corrected run used an exec tmpfs and an explicit no-installer mock.

The new runner guard checks the marker for the state snapshot actually selected
by the interval, before first-session reservation, without waking the bot.
An internal deferred result makes the scheduler retain the due task without a
run log or notification. The regression follows the real selection callback,
checks state/session/marker and the unchanged task, then wakes Codex and verifies
one execution. It also checks an alternate bot profile, first-session reserve,
Claude and direct turns, unreadable marker, /stop, and a contended marker lock.

Run from iia root:
  node .msb/bot/tests/reference/probe-codex-provider-pause.mjs
  node --test .msb/bot/tests/interval-provider-pause.test.mjs
The test wrapper enables module mocks in an isolated child and now asserts all 12
synthetic scenarios, including Codex pause while the task lock is held. Provider changes or markers written by another process
after the captured state/marker check remain a separate non-atomic boundary;
/stop of an already started interval and shared task ownership are not fixed.

Validation: local Node 26 and isolated Linux arm64 Node 22.23.2 each passed
37 related top-level tests (the interval-provider wrapper runs 11 additional
synthetic cases), two selected Codex/Claude interval-pause cases, five selected
Codex/Claude switch cases, and six selected provider-session cases. The
selections exclude unrelated engine behavior; the status/dispatcher fixtures
are mocked before import. Both model runners and Telegram are synthetic.
The prior interval-claim stage separately validated native better-sqlite3;
that original provider-guard stage used the existing Node SQLite fallback.
A later interval-admission stage also ran the expanded wrapper on native
better-sqlite3; its details are in parity-interval-claim-contract.txt.
