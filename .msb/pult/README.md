# Пульт

Панель состояния сервера ботов MSB: что делают боты, какие фоновые задачи крутятся, проекты и ресурсы сервера. Сверху — «Нужно от тебя» и «Требует внимания». Тревоги о серьёзных сбоях и сводка в 08:00 МСК — в Telegram.

**Поставка:** канон этого репо; в ядре MSB — вендор-копия `.msb/pult/` (`./scripts/sync-pult.sh`). Сток-конфиг — `~/.msb/bots` + `msb-bot@` + платформенные таймеры MSB, без продуктовых сервисов. Включение на боксе: `/settings` → Системные → Пульт.

История: поручение 29.10.2026 (тогда IIA). Концепты UI — `concept/`.

Решения Михаила 29.10.2026: отдельный веб-сервис по постоянной ссылке (Telegram доступен ему не всегда) — `https://pult.dev.mp.aaa0.ru`; веб-сервис живёт на сервере ботов и за ним следит личный бот (30.10: «сам за ним будешь следить»), TLS и домен держит nginx Михаила; первая версия только показывает, кнопок управления нет; тревоги — только о серьёзном (служба упала, фон завис, память или диск заняты больше чем на 90 %) и сводка в 08:00; статус «Задач с созвонов» с другого сервера — вторым этапом.

## Как устроено

```
сервер ботов (192.168.33.203 в сети Михаила)
┌──────────────────────────────┐ POST /api/ingest ┌──────────────────────────────────────────┐
│ pult-collector (раз в минуту)│ ───────────────► │ pult-web 127.0.0.1:8791: вход (пароль +  │
│ журналы ботов, systemd,      │  Bearer-токен    │ код), API, SQLite (снимок, история 35 дн,│
│ /proc, git, реестры;         │                  │ сессии), тревоги и сводка 08:00 → Telegram│
│ сторож: веб 10 мин не        │                  └──────────────────▲───────────────────────┘
│ принимает → тревога сам      │                       nginx 192.168.33.203:8792 (только из сети)
└──────────────────────────────┘                                     ▲ http, локальная сеть
   ▲ pult ask / pult project (боты)                nginx Михаила: https://pult.dev.mp.aaa0.ru (TLS)
   └── ~/workspace/ops/pult/{asks,projects}.json                     ▲ браузер Михаила: src/ui
```

- **Сборщик** (`src/collector/`) — только чтение, без ИИ и без трат. Раз в минуту собирает снимок по контракту `src/shared/types.ts` и отправляет веб-сервису. Не прочитал источник — не выдумывает: поле пустое, причина в `sourceErrors`, на панели внизу «Не удалось прочитать». Правила «требует внимания» — `src/collector/analyze.ts`, пороги — `config/pult.config.json → thresholds`.
- **Веб-сервис** (`src/server/`) — принимает снимки, хранит последний и историю нагрузки, отдаёт интерфейс и API только после входа, шлёт тревоги и сводку. Может жить на другом сервере: связь со сборщиком — только HTTP.
- **Снаружи** — `https://pult.dev.mp.aaa0.ru`: TLS и домен на nginx Михаила, он проксирует по локальной сети на `http://192.168.33.203:8792` — местный nginx (`deploy/nginx-pult.conf`). Тот слушает только адрес в сети, пускает только `192.168.33.0/24`, берёт IP пользователя из `X-Real-IP`, ограничивает частоту `/login` и при недоступном веб-сервисе отдаёт понятную страницу `deploy/pult-down.html`.
- **Mini App** — кнопка «Пульт сразу» (меню бота и под сообщениями). Вход без пароля: в URL кнопки билет `?tg=…` (неделя; обновляется со сводкой, тревогой, `send-test` и на любое сообщение владельца боту). Меню Mini App — только у владельца (`PULT_TG_CHAT_ID`); чужим бот молчит. Запасной путь — подпись `initData`. Страница входа на «/» без билета — 200 без редиректа, чтобы не потерять `#tgWebAppData`. В браузере по обычной ссылке — пароль + код.
- **Кто следит за самим Пультом:** упала служба и systemd перестал её поднимать — тревога через `pult-notify-failure@`; веб-сервис 10 мин не принимает снимки (завис, отвечает ошибкой) — тревогу шлёт сборщик (`src/collector/watch.ts`); сборщик молчит 5 мин — тревогу шлёт веб-сервис.
- **Интерфейс** (`src/ui/`) — статические файлы без сборки и зависимостей; вкладки Обзор · Боты · Задачи · Проекты · Сервер, карточка задачи; на телефоне — одна колонка и нижнее меню. С 06.11.2026 (v3): progressive disclosure — на Обзоре норма (боты, расписание, остатки) свёрнута, asks компактны; на Задачах группа «В норме» свёрнута, колонки «Чего ждать» нет; cron и легенды — во втором уровне. Макеты — `concept/v3/`.
- **Реестры** — вопросы к Михаилу и карточки проектов. Ведут боты командой `bin/pult` (правило в общем `~/workspace/CLAUDE.md`, раздел «Боты на одном сервере»). Остальное сборщик берёт сам: службы, коммиты, фоновые задачи, нагрузку.

Названия платформы ботов, её служб и пути к её файлам в снимок и на экран не попадают — только «Основной», «SMM», «Личный», «Sales» и «служебные процессы платформы ботов: N, в норме».

**Новый бот:** каталог в `botsRoot` (`~/.msb/bots/<id>`), которого ещё нет в `bots` конфига, подхватывается сам (`discoverExtraBots`) — карточка с юнитом `msb-bot@<id>.service`.

## Вход и безопасность

- Пароль (`PULT_PASSWORD`, задаёт Михаил) + код из приложения-аутентификатора (TOTP). QR-код для приложения показывается один раз, при первом входе; сброс — `node src/server/admin.ts reset-2fa --yes`.
- Устройство запоминается на 30 дней (cookie HttpOnly, Secure, SameSite=Strict; в базе — только хеш).
- Подбор: 5 неудач с одного адреса за 15 мин — пауза; 20 неудач за час со всех адресов — тревога в Telegram; nginx ограничивает частоту запросов к `/login`.
- О каждом входе с нового устройства и о подключении второго фактора приходит сообщение в Telegram.
- Строгие заголовки (CSP без инлайн-скриптов, запрет фреймов, noindex). Сборщик пишет только с токеном `PULT_INGEST_TOKEN`.

## Статус и открытые вопросы

**Статус (30.10.2026):** первая версия собрана: 239 тестов зелёные, сквозная проверка в браузере на живых данных пройдена. Код, службы и вход для nginx Михаила (`192.168.33.203:8792`) выложены; веб-сервис ждёт пароль.

Решено по ходу (29.10): история нагрузки пишется по времени сбора снимка (часам сборщика не верим, если они «в будущем» больше чем на 5 мин); у ботов «чем занят» — по последнему сообщению после последнего ответа, «последний итог» — по последнему непустому ответу (оборванные ходы оставляют пустые); `Referrer-Policy: same-origin` — с `no-referrer` браузер шлёт формам `Origin: null`, и защита от подделки запросов не отличает свои формы; токен сборщика — только ASCII (уходит в HTTP-заголовок); журнал systemd читает только служба сборщика (`SupplementaryGroups=systemd-journal`). Переменная `PULT_TG_API_BASE` — подменный Telegram для тестов.

Открытые вопросы:
- **nginx Михаила** — `https://pult.dev.mp.aaa0.ru` → `http://192.168.33.203:8792` (Михаил, 30.10). После первых запросов сузить `--allow` до адреса его nginx (виден в `/var/log/nginx/pult.access.log`).
- **Пароль и бот уведомлений** — Михаил задаёт `PULT_PASSWORD` и `PULT_TG_TOKEN` в `/settings` личного бота. Без пароля веб-сервис не запускается; без токена — работает, но тревоги и сводка не уходят (на панели — подсказка).
- **Трафик между nginx Михаила и сервером ботов** идёт по локальной сети без шифрования (пароль и cookie входа). Сеть своя; если понадобится — TLS на `:8792` с самоподписанным сертификатом и его закреплением у nginx Михаила.
- **Второй этап:** статус «Задач с созвонов» с сервера Михаила (они пришлют свой снимок на тот же `/api/ingest`).
- **Подписки разделены по провайдерам:** прежний Claude-маршрут читает `state.rateLimitInfo` (статус и сброс). Codex читает измеренные проценты и окна через штатный `account/rateLimits/read`, раз в 5 минут; API-ключи и другие CLI не получают фиктивную квоту Claude. Новые чат-ходы пишет общий lifecycle open-core. [Маршруты, проверки и границы](../../docs/pult-telemetry.md).
